## 1. 背景与产品定位

传统 IDE 的编码区是给"人写代码"用的。本项目要做的是**把写代码这件事整体交给 AI Agent**，人只负责：

- 选项目 → 看结构 → 下指令 → 看 Agent 干活 → 审阅结果 → 提交推送。

因此产品形态不是"编辑器 + 插件"，而是 **一个多 Agent 的控制台（Agent Control Plane）**：

- 没有可编辑的代码区（最多只读预览 / diff 审阅）；
- 有多个并行的 Agent 会话，每个会话是一个真正的 `claude` CLI 进程；
- 有一个"项目经理 Agent"负责分派任务、维护上下文、协调多 Agent；
- Git 操作也由 Agent 完成（读 diff → 写提交信息 → commit → push）。

一句话：**AIDE = 项目工作区 + 多 Agent 会话调度 + AI 生成的 Git 流水线。**

### 2.2 隐含需求（用户未明说但必须做）

1. **会话持久化与恢复**：关掉浏览器/重启服务后，会话列表与聊天记录还在；再次发消息用 `claude --resume <session_id>` 续上。
2. **进程生命周期管理**：Agent 卡死、崩溃、停止、重启；Windows 下要杀进程树。
3. **实时性**：Agent 思考/工具调用/输出必须流式可见，而不是等 30 秒一次性返回。
4. **成本可见**：claude 每条 result 都带 `total_cost_usd`、token 用量，应聚合成会话/项目/当日成本。
5. **并发安全**：多个 Agent 同时改同一份工作区会互相覆盖 → 必须有写锁/队列（或 worktree 隔离）。
6. **可审阅性**：Agent 改了什么必须能看见（文件 diff、工具调用记录），否则"一键提交"是盲提交。
7. **失败可诊断**：CLI 未登录、模型不可用、额度耗尽、端口占用等，要有明确错误提示而不是转圈。

### 2.3 明确不做（MVP 范围外，可后续迭代）

- 代码编辑、补全、语法高亮编辑、LSP 诊断面板；
- 用户体系 / 多租户 / 权限管理（本地单用户）；
- 远程项目（SSH）、容器化开发环境；
- 代码评审工作流（PR/MR 集成）、CI 看板。

## 3. 关键设计决策（需确认）

### D1. Agent 引擎：长驻进程 + stream-json 双工

已实测（claude 2.1.224，Windows）：

```
claude.exe -p --input-format stream-json --output-format stream-json --verbose
```

- stdin 逐行写 `{"type":"user","message":{...}}`，可**同一进程连续多轮**；
- stdout 逐行输出 NDJSON：`system/init`（工具清单、cwd、session_id）、`thinking_tokens`、`assistant`（thinking/text/tool_use）、`user`（tool_result）、`result`（耗时、cost、usage、stop_reason）；
- `--session-id <uuid>` 指定会话 ID；`--resume <uuid>` 恢复历史（实测：第二轮正确回忆第一轮内容）；
- 原生 `claude.exe` 可直接被 Java `ProcessBuilder` 启动（`C:\Users\<user>\AppData\Roaming\npm\node_modules\@anthropic-ai\claude-code\bin\claude.exe`），**不需要 cmd.exe 包装**，避免 Windows 引号地狱。

结论：每个 Agent 会话 = 一个长驻 `claude.exe` + 一条 stdin 管道 + 一个 stdout 解析器。这是"终端感"与"结构化状态"的最佳折中。

### D2. 管理 Agent：自身也是 claude 会话，通过 IDE 工具编排其他会话

两种实现路径：

- **A（推荐）MCP 工具桥**：应用内置一个极小的 stdio MCP Server（Node 脚本，`aide-mcp.mjs`，零外部依赖），暴露工具：
  - `aide_list_sessions` / `aide_get_session`：看有哪些 Agent、在干什么、最近说了什么；
  - `aide_create_session`：新建 Agent（名称、角色、初始任务）；
  - `aide_send_message`：把任务派发给某个会话；
  - `aide_git_status` / `aide_commit_push`：查变更、提交推送；
  - `aide_list_projects`。
  项目经理的系统提示词规定"简单问题自己答，需要改代码/排查/构建就派发"，其工具调用在 UI 上渲染成**派发卡片**，可点击跳转。
- **B 结构化路由**：项目经理只输出 `{"action":"dispatch","sessionId":...}` 之类的 JSON，由后端执行。简单可控，但无法多步编排、无法读取会话近况。

### D3. 并发与工作区隔离

同一项目多个 Agent 同时写代码 = 灾难。三个选项：

- **单写者锁 + 队列（推荐 MVP）**：同一项目同一时刻只有一个"写入型"会话在跑，其余排队（显示"排队中"）；只读型会话（问答/审查）可并行。
- **每会话 git worktree**：真正并行，但要处理分支合并/冲突，复杂度高一个量级。
- **完全并行同工作区**：实现最快，但结果不可控。

### D4. Git 由谁执行

- **专用临时 Git 会话（推荐）**：点"一键提交并推送"时，后端聚合 `git status` + `git diff`，起一个短生命周期的 claude 会话（只给只读 + git 工具），要求输出符合 Conventional Commits 的提交信息，由后端执行 `git add -A && git commit && git push`，Agent 只负责"写描述 + 解释变更"；执行结果写回记录。
- 也可让项目经理或当前选中会话执行，但会污染业务上下文，且业务会话可能正在跑，容易队列互锁。
- 附带：提交前必须展示 diff 摘要供用户确认（可配置"免确认"）。

### D5. Claude 权限模式

Agent 全自动改代码，权限必须预先决定：

- `--permission-mode acceptEdits`：自动接受文件编辑，Bash 等仍按规则（推荐，配合 IDE 侧白名单）；
- `--permission-mode bypassPermissions`：全放开，最快也最危险；
- `manual` + IDE 内审批弹窗：最安全，但需要 `--permission-prompt-tool` 回调，工作量最大（P2 再做）。

## 4. 总体架构

```
┌──────────────────────────────── Browser ────────────────────────────────┐
│ React 19 + TypeScript + Vite + Tailwind                                  │
│  项目栏 │ 文件树 / 会话列表 / Git 树 │ 会话流(SSE) │ 只读预览·Diff        │
└───────────────▲──────────────────────────────┬──────────────────────────┘
                │ REST (JSON)                  │ SSE (text/event-stream)
┌───────────────┴──────────────────────────────▼──────────────────────────┐
│ Spring Boot 3.x (Java 21) — AIDE Server                                  │
│                                                                          │
│  ProjectService   FileService    GitService(JGit/CLI)                    │
│  AgentRuntime  ── SessionProcess(stdin/stdout NDJSON) ── EventBus        │
│  ManagerService  ── Router / Dispatcher                                  │
│  McpBridge(stdio) ── aide-mcp.mjs ──► REST                               │
│  Persistence: H2 file DB + 会话消息表                                     │
└───────────────┬──────────────────────────────────────────────────────────┘
                │ ProcessBuilder
        ┌───────▼────────┐   ┌────────────────┐
        │ claude.exe #1  │   │ claude.exe #N  │   cwd = 项目根目录
        │ (项目经理)      │   │ (业务 Agent)    │   --session-id / --resume
        └────────────────┘   └────────────────┘
```

**为何后端选 Java**：主题是"Java Web 开发为主的 IDE"，后端用 Spring Boot 与目标用户心智一致，也便于后续扩展 Java 项目专属能力（Maven/Gradle 构建、Spring 配置解析、依赖分析）。

> 注意：当前机器只有 **JDK 8**（`C:\Users\<user>\.jdks\corretto-1.8.0_492`），无 Maven/Gradle。做 Spring Boot 3 需先安装 **JDK 21**（winget 可装）+ Maven Wrapper（`mvnw`，随仓库提交，无需全局 Maven）。

## 5. 数据模型（草案）

```sql
project(id, name, path, color, sort_no, created_at, last_opened_at)
session(id, project_id, claude_session_id, title, role, model,
        status, created_at, updated_at, last_active_at,
        total_cost_usd, turns, tokens_in, tokens_out, last_error,
        is_manager, parent_session_id)
message(id, session_id, seq, role, kind, payload_json, created_at)
        -- kind: text | thinking | tool_use | tool_result | result | system | error
git_op(id, project_id, kind, status, commit_sha, message, detail, created_at)
setting(key, value)
```

会话状态机：

```
QUEUED ──► STARTING ──► RUNNING ⇄ THINKING
                │            │
                │            ├─► WAITING_INPUT（进程存活，本轮结束）
                │            ├─► WAITING_PERMISSION（可选）
                │            └─► ERROR
                └──────────► STOPPED（用户停止 / 进程退出）
```

## 7. UI 布局（方案 A）

```
┌──────┬──────────────────────────┬──────────────────────────────────────────┐
│ 项目 │ ▾ 文件                    │ ★ 项目经理                        ● 运行中 │
│      │    src/                   │ ───────────────────────────────────────  │
│ AIDE │      main/java/…          │ 你：给订单列表加分页                       │
│ ● 3  │      resources/…          │ 经理：这是后端改动，已派发给「后端-订单」并   │
│      │    pom.xml          M     │       让它先补测试。                      │
│ Shop │                           │  ┌ 派发 → 后端-订单 ────────────────┐    │
│ ● 1  │ ▾ AGENT 会话 (4)          │  │ 为 OrderController 加分页参数…    │    │
│      │    ★ 项目经理    running  │  └──────────────────────────────────┘    │
│      │    ● 后端-订单   running  │  ▸ 工具 Bash   mvn -q test  ✅ 12s        │
│      │    ● 前端-列表   idle     │  ▸ 改动 3 个文件  (+120 −8)               │
│      │    ○ 测试       error    │ ───────────────────────────────────────  │
│  +   │                           │ [ 描述你的需求…                  ] [发送]  │
│      │ ▾ GIT  main ↑2            │                                          │
│      │    3 个未提交更改          │                                          │
│      │    ● 9f2a1c 修复分页越界   │                                          │
│      │    ○ 4d1e77 新增订单接口   │                                          │
│      │    [ 一键提交并推送 ]      │                                          │
└──────┴──────────────────────────┴──────────────────────────────────────────┘
```

交互要点：

- 左栏三段可折叠，宽度可拖拽；主区按会话开 Tab（像终端），切换不丢流。
- 未选中会话时，主区默认是项目经理会话。
- 项目徽标：运行中会话数（脉冲点）+ 未提交文件数 + 是否有冲突。
- 会话行：状态色点 + 名称 + 角色标签 + 耗时/费用 + 最近一行摘要。
- Git 行：分支、ahead/behind、提交图（lane 简化版）、变更文件数、按钮。
- 一键提交 → 侧滑面板：变更列表 + diff 摘要 + Agent 生成的提交信息（可编辑）→ 确认 → 进度/结果。
- 右侧检查器（可关）：文件只读预览、diff、工具输出详情。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 机器无 JDK 21 / Maven | 后端无法构建 | 用 winget 安装 JDK 21；提交 `mvnw` 包装器 |
| Windows 进程/编码问题 | 中文乱码、进程杀不掉 | 统一 UTF-8 读写；`taskkill /T /F` 杀进程树；避免 cmd.exe 包装 |
| claude 未登录/额度/模型不可用 | 会话全线失败 | 启动自检 + 明确错误码；会话级错误气泡 + 重试 |
| 多 Agent 并发改同一工作区 | 代码互相覆盖 | 单写者锁 + 排队；后续 worktree |
| 上下文/费用失控 | 账单飙升 | 每会话成本上限告警；自动 compact 提示；模型可选 |
| 大仓库文件树卡顿 | 首屏慢 | 懒加载 + 忽略 `.git/node_modules/target` + 虚拟滚动 |
| MCP 协议版本漂移 | 工具调不通 | 固定 claude 版本范围；MCP 桥做兼容层；降级为结构化路由 |
| "盲提交"风险 | 提交了不该提交的内容 | 提交前 diff 摘要 + 确认；`.gitignore` 校验；敏感文件告警 |

### 默认假设（若无异议按此执行）

- 本地单用户，无登录鉴权；仅监听 `127.0.0.1`。
- 项目 = 已存在的本地目录，通过路径注册；暂不做 clone/新建项目。
- 文件树可点击查看**只读**内容与 diff，不可编辑。
- 中文界面；深色主题为主。
- 数据库 H2 文件模式，数据目录 `<project-root>\data`。
- 会话支持角色模板：后端 / 前端 / 测试 / 代码审查 / 自由。
