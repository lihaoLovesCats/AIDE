## 1. 决策清单

| 编号 | 决策点 | 结论 |
|------|--------|------|
| D1 | 实现栈 | **Node.js 24 + TypeScript**（Fastify）+ React 19 + Vite + Tailwind 4 |
| D2 | Agent 引擎 | **每会话一个长驻 `claude.exe` 进程**，stdin/stdout 双工 `stream-json` |
| D3 | 会话恢复 | 持久化 `claude_session_id`，进程退出后用 `--resume` 重建 |
| D4 | 项目经理 | **MCP 工具桥**：经理是普通 claude 会话，通过 `aide_*` 工具编排其他会话 |
| D5 | 并发隔离 | **每会话独立 git worktree + 分支**（`aide/<slug>`），基线 = 创建时 main HEAD |
| D6 | 分支回收 | 会话完成后在 Git 面板「合并回主干」，冲突时自动拉起**合并 Agent** |
| D7 | 提交执行者 | **专用临时 Git 会话**生成提交信息，后端执行 `git add/commit/push` |
| D8 | 权限 | `--permission-mode bypassPermissions`（全自动），辅以路径/命令护栏 |
| D9 | 布局 | 方案 A：项目竖排 → 文件/会话/Git 三段可折叠 → 主区会话流 → 右侧检查器 |
| D10 | 运行与预览 | 一等功能：每 worktree 独立实例，**自动分配端口**（18080+）并记录 |
| D11 | 数据存储 | SQLite（`node:sqlite`，零原生依赖），数据目录 `data/aide.db` |
| D12 | 目标领域 | 多语言 Web/应用项目（Java、Python、Node/JS/TS，兼顾 Go/Rust/静态页），自身栈与领域解耦 |

### 2.1 会话进程契约

```bash
claude.exe -p \
  --input-format stream-json --output-format stream-json --verbose \
  --session-id <uuid> \
  --permission-mode bypassPermissions \
  --add-dir <projectRoot> \
  --mcp-config <tmp>/aide-mcp.json \
  --append-system-prompt "<角色提示词>"
```

- **输入**：`{"type":"user","message":{"role":"user","content":[{"type":"text","text":"…"}]}}`
- **输出**：`system/init`、`assistant`（thinking / text / tool_use）、`user`（tool_result）、`result`（cost、usage、stop_reason）
- 进程存活期间可连续多轮，无需重启；空闲超过 30min 可回收，下次 `--resume` 冷启动
- 环境变量：`AIDE_SESSION_ID`、`AIDE_PROJECT_ID`、`AIDE_API`、`AIDE_TOKEN`（供 MCP 桥回调）

### 2.2 MCP 工具（项目经理可见）

| 工具 | 作用 |
|------|------|
| `aide_list_sessions` | 列出项目下所有 Agent：名称、角色、状态、分支、最近一条活动、费用 |
| `aide_session_tail` | 读取某会话最近 N 条消息，用于判断"这个任务该给谁" |
| `aide_create_session` | 新建 Agent（名称、角色模板、初始任务），自动建 worktree |
| `aide_dispatch` | 把任务派发给指定会话（遵守单项目写锁与队列） |
| `aide_git_status` | 当前主干与各分支的变更摘要 |
| `aide_commit_push` | 触发一键提交（生成信息 → commit → push → 合并） |
| `aide_run_app` | 启动/停止某会话的实例，返回端口与预览地址 |

MCP 桥是 `aide-mcp.mjs`：stdio JSON-RPC ↔ 本地 REST，带 `AIDE_TOKEN`，随每个 claude 进程注入临时 config。

### 2.3 Worktree 生命周期

```
创建会话 → git worktree add .aide/worktrees/<slug> -b aide/<slug> main
运行中   → Agent 在独立目录改代码，互不干扰
提交     → 在 worktree 内 commit → push origin aide/<slug>
合并     → 切回 main worktree：git merge --no-ff aide/<slug>
           冲突 → 启动合并 Agent（专用会话，带冲突文件清单）
清理     → 合并成功后 worktree remove + 分支可保留/删除
```

- 主干工作区保持干净，只做合并与运行；
- 每个 worktree 独立运行实例与端口，日志按会话归档；
- 磁盘占用：`target/` 不共享，首次编译较慢 → 可选 Maven 本地仓库共享（默认已共享 `~/.m2`）。

### 2.4 运行与预览

- 启动命令可配置：`mvn spring-boot:run -Dspring-boot.run.arguments=--server.port={port}`
- 端口池：18080–18120，占用检测后顺延，写入 `runs` 表
- 健康检查：轮询 `http://127.0.0.1:{port}/actuator/health` 或 TCP 连通
- UI：运行面板展示实例列表、实时日志（环形缓冲 2000 行）、一键打开浏览器

### 2.5 安全护栏（bypassPermissions 前提下）

1. `--add-dir` 仅注入项目根与 worktree，禁止访问用户主目录其他路径（尽力而为）；
2. 危险命令前置拦截：`rm -rf /`、`format`、`shutdown`、`git push --force`（可配置）；
3. 提交前强制展示 diff 摘要与敏感文件（`.env`、密钥）告警；
4. 所有 Agent 命令与工具调用落库，可审计；
5. 服务仅监听 `127.0.0.1`。

## 3. 数据模型

```sql
project(id, name, path, color, main_branch, run_port, created_at, last_opened_at)
session(id, project_id, claude_session_id, title, role, model, status,
        worktree_path, branch, base_sha, port, run_status,
        cost_usd, tokens_in, tokens_out, turns,
        last_activity, last_error, is_manager, created_at, updated_at)
message(id, session_id, seq, role, kind, payload_json, created_at)
        -- kind: text | thinking | tool_use | tool_result | result | system | error
git_op(id, project_id, session_id, kind, status, commit_sha, message, detail, created_at)
run(id, project_id, session_id, port, pid, status, started_at, stopped_at)
setting(key, value)
```

状态机：

```
CREATED → QUEUED → STARTING → RUNNING ⇄ THINKING
                        │           ├→ WAITING_INPUT（本轮结束，进程存活）
                        │           ├→ ERROR（进程退出码≠0 / 上下文超限）
                        │           └→ STOPPED（用户停止）
                        └→ MERGED（分支已合回主干）
```

## 8. v0.3 增量（原型第二轮反馈）

> 依据 2026-11-16 的 7 条反馈落地，均已进入原型并逐项验证。

### 8.1 左栏可拖拽分栏
- 三段高度用 `sizes: [number, number, number]`（fr 比例）表示，默认 `0.30 / 0.42 / 0.28`；
- 两条 6px `role="separator"` 分隔条，Pointer Capture 拖拽，最小比例 14%，双击复位；
- 折叠的段落使用 `auto` 行高，不参与比例分配，避免"折叠后留白"；
- 正式版把比例持久化到 `settings` 表（`ui.splitter`）。

### 8.2 派发卡片：判断依据、置信度、改派/撤销
- `DispatchRef` 增加 `reason: string`、`confidence: number`，状态扩展 `revoked`；
- 卡片展示判断依据、置信度条（94% / 87%），操作：跳转 / 改派 / 撤销；
- 改派从当前项目的 Worker 列表中选择，后端需把"派发"落为可变更的 `dispatch` 记录（含审计），
  并同步目标会话的写锁归属；
- 撤销时目标 Agent 回到空闲，任务文本删除线 + `已撤销` 状态，同样进入审计。

### 8.3 状态机补充
```
WAITING_USER        等待用户确认（Agent 提出问题，阻塞本轮）
WAITING_PERMISSION  等待授权（DDL / 危险命令，按权限策略阻塞）
```
- 进入条件：claude 的 `permission_denials`、或系统提示词要求"遇到 DDL/删除类操作先确认"；
- UI：会话列表状态点（琥珀 / 粉色）+ 聊天区顶部横幅，直接给出选项按钮；
- 授权结果回写为一条 user 消息（`批准执行 DDL` / `拒绝执行`），继续 `--resume` 同一会话；
- 正式版接 `--permission-prompt-tool` 或 IDE 侧 MCP 审批工具，把结果回传 CLI。

### 8.4 提交门禁（mvn test）
- 提交弹窗新增开关"提交前运行 `mvn test`，失败则中止推送"（默认开）；
- 步骤编排：汇总变更 → Git Agent 生成描述 → **mvn test** → commit → push → 合并；
- 失败：`phase=failed`，展示 `Tests run / Failures` 与具体断言，`git add/commit/push` 全部不执行；
- 正式版读取真实退出码，超时（默认 10 分钟）与 OOM 也按失败处理，日志落 `git_ops.detail`。

### 8.5 运行面板：多实例 + 端口
- 左侧实例列表：每个 worktree 一行（名称、分支、端口、运行状态、启停按钮）；
- 右侧日志绑定选中实例，SSE 实时追加；
- 端口内联编辑：范围 18080–18120、查重、回车/失焦生效，失败回填并提示；
- 「预览」用 `window.open(..., '_blank')` 打开，正式版指向真实实例；
- 原型用 `public/preview.html` 模拟被开发应用（订单表格 + 分页），带端口/分支/会话信息。

### 8.6 主题与字号
- 颜色全部走 CSS 变量（`@theme` 生成 `--color-*`），叠加层用语义变量
  `--color-soft / --color-hover / --color-sunken`，浅色主题只需覆盖变量；
- `html.theme-light` 覆盖整套调色板（含状态色降饱和加深），`color-scheme: light`；
- 字号/密度：`html.style.zoom` 三档 `0.92 / 1 / 1.06`，整体缩放不破坏布局；
- 设置入口在顶栏齿轮，原型仅保存在内存，正式版落 `localStorage` + `settings` 表。

### 8.7 分支与合并面板
- 入口：Git 区标题「分支 N」、分支卡片、`GitMerge` 图标；
- 表格列：分支、领先/落后、最近提交（含时间）、状态（干净/有改动/冲突）、操作（会话/合并）；
- 合并走 `git merge --no-ff`，成功后分支变为干净、主导航追加 merge 提交；
- 冲突：原型以 `aide/test-regression` 演示"检测到 2 个冲突文件 → 启动合并-解决冲突 Agent"；
- 正式版把冲突清单作为上下文注入新建的合并会话，解决后再完成合并。

## 9. v0.4 增量（第三轮反馈）

### 9.1 强制提交（二次确认）
- 入口只在测试失败态出现：「仍然提交…」→ 展开红色确认区（说明风险）→「确认强制提交」；
- 执行：跳过 test 阶段继续 commit → push → merge，步骤行显示 **已跳过（强制提交）**（红色），不再显示 `412 passed`；
- 审计：正式版写 `git_ops`（`forced=true`、失败用例列表、操作者、时间）并给项目经理会话发一条通知；
- 约束：默认关闭、每次都要重新确认、不可撤销；CI 仍会拦截，不作为常规路径。

### 9.2 撤销派发 = 通知 Agent 回滚
- 撤销时向目标会话注入一条 `system/notice`（斜线分隔的居中提示）与一条 user 指令：
  "任务已撤销，请停止改动并回滚未提交的修改"；
- Agent 回报回滚结果（`git reset --hard HEAD` / checkout），会话回到空闲，activity 变为"已回滚，工作区干净"；
- 数据模型：`dispatch.status=revoked`、`revoked_at`、`notify_message_id`；
- 注意：若会话正在跑，消息按队列在下一轮送达；若已产生提交，回滚用 `git revert` 而非 `reset --hard`，原型只演示未提交场景。

### 9.3 资源监控与启动准入
- 监控项：CPU、可用内存、每实例 RSS；2s 采样；
- 准入规则：`预计内存 = 46% + 实例数 × 8%`，超过 **80%** 拒绝启动，UI 在日志区顶部给出琥珀色横幅（含当前/预计值），Header 常驻 CPU/内存水位条；
- 不做排队：按"资源紧张时不要新运行实例"直接拒绝，提示先停空闲实例；
- 真实实现：`os.freemem()/totalmem()`、`os.loadavg()`、按 PID 采样（Windows 用 `Get-Counter`/`wmic`），恢复准入加滞回（低于 72% 才恢复）；端口范围维持 18080–18120。

### 9.4 主题 / 缩放持久化
- `localStorage`：`aide.theme`（dark/light）、`aide.zoom`（compact/normal/comfort）；
- `index.html` 内联脚本在首屏渲染前恢复 `theme-light` 与 `zoom`，避免闪白；
- React 初始化读取同一 key，切换时回写；正式版同时写 `settings` 表，并增加"跟随系统"选项（`prefers-color-scheme`）。

### 10.1 落地情况

### 10.2 与方案的偏差
| 方案 | 实际 | 原因 |
|------|------|------|

## 19. 打包与分发（内部测试）

### 19.1 方案
- 自带 `node.exe`（win-x64），测试机不需要安装 Node.js；
- 服务端用 esbuild 打成**单文件 ESM**（约 1.9MB），不携带 node_modules；CJS 依赖里的动态 `require`
  通过 banner 注入 `createRequire(import.meta.url)` 兜底；
- 前端 `prototype/dist` → `app/web`，MCP 脚本 → `app/server/mcp`；
- 运行数据默认 `%APPDATA%\AIDE`，可用 `AIDE_DATA` 覆盖；启动脚本设置 `AIDE_DATA` / `AIDE_WEB_DIST`；
- `start-aide.cmd` 先做健康检查（已运行则只打开浏览器），再前台启动 node 并自动打开浏览器；
- `stop-aide.cmd` 读取 `server.pid`，用 `taskkill /T /F` 结束整个进程树（含 claude 子进程）；
- Inno Setup 6 生成用户级安装包（`%LOCALAPPDATA%\Programs\AIDE`），含开始菜单、停止快捷方式与卸载程序；
  安装包未签名，安装向导为英文。

### 19.2 为什么不用 node_modules
- 首次尝试 `npm install --omit=dev` + ZIP：依赖包内的测试 fixture 含 Windows 非法文件名
  （`100%.txt`、结尾空格/反斜杠等），`Expand-Archive` 与 Inno 解压失败；
- 改为 esbuild 单文件 bundle，既规避非法文件名，也把安装包压到约 23MB（ZIP 33MB）。

### 19.3 产物
- `dist-package/AIDE-0.3.0-win-x64.zip`（约 33.2MB，免安装）；
- `dist-package/AIDE-Setup-0.3.0.exe`（约 23.4MB，用户级安装）；
- `dist-package/SHA256SUMS.txt`。

### 19.4 验证
- 免安装：解压 → `start-aide.cmd` → `/api/health` 与首页正常 → 数据目录创建 → `stop-aide.cmd` 停止、端口释放；

## 22. SVN 与项目知识（2026-11-18）

### 22.1 VCS 模型
- `projects` 增加 `vcs`（`git` / `svn` / `none`），保留 `is_git` 兼容旧数据；迁移按 `is_git` 回填；
- 注册时检测 `.git` / `.svn`：Git 读取当前分支，SVN 读取 `svn info` 的 `relative-url`（如 `^/trunk`）；
- Git 会话照旧使用独立 worktree + `aide/*` 分支；SVN 与非版本控制项目使用项目根目录；
- 文件树状态、项目状态/日志/差异、会话状态、提交接口按 `vcs` 分派；合并/清理仅 Git。

### 22.2 SVN 实现
- `server/src/svn.ts`：`isSvnRepo`、`svnAvailable`、`svnInfo`、`svnStatus`、`svnLog`、`svnDiff`、`svnCommit`；
- 所有命令带 `--non-interactive`，避免凭据提示挂起；状态/日志走 XML，路径过滤 `.svn`、`.aide`、`node_modules` 等；
- `svn log` 使用 `-r HEAD:1`，不依赖可能未更新的工作副本 BASE；提交版本号优先解析输出，失败时回退 `HEAD` 日志；
- `svnCommit` 会先 `svn add --parents` 未版本控制的新文件，再 `svn commit -m`；
- `server/src/svncommit.ts`：测试门禁 → AI 提交信息 → SVN 提交 → 审计/SSE，返回 `sha=rN`、`remote=svn`、`pushed=true`；
- UI：Git 区块按 `vcs` 显示 `SVN`，分支显示 `^/...` + `working copy`，提交按钮文案「提交到 SVN」，隐藏分支/合并；
- 限制：SVN 没有 per-agent worktree，所有 Agent 共享工作副本，并发写需自行协调；不支持分支/合并/推送。

### 22.5 限制
- SVN 共享工作副本，多个 Agent 同时改同一文件会互相覆盖；建议按模块分工或串行；
- SVN 不提供分支/合并/worktree；需要分支时请在外部 SVN 客户端处理；
- 需要本机安装 `svn` 命令行（SlikSVN/TortoiseSVN CLI）；缺失时状态/提交返回明确错误；
- 知识生成是提示词约束为只写 `.aide`，未做文件系统沙箱；生成质量取决于项目可读信息；
- `.aide` 默认不提交；如需团队共享需手动加入版本控制。
